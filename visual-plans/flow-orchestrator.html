Technical Plan

Flow → Workflow Orchestrator & Lanager Runtime

Turn the flow-tab plugin from a hardcoded browser/RPA driver into a general workflow orchestrator: every BOSS & external tool becomes a node, workflows become agent-driven "lanagers," and Claude Code can author them over MCP.

Scope L (multi-phase program) Touches flow-tab plugin · boss-plugin-api (compileOnly) · terminal-tab (runtime dep) Risk med-high Date 2026-07-07 Status Draft for review · red-teamed

00TL;DR

Refactor Flow's closed node enum into an open NodeSpec registry, then feed that registry from a unified tool layer so tools, browsers, and agents all become nodes - and expose a fixed set of MCP tools so Claude Code can build workflows itself.

  • Consume, don't build. The host already has the "toolkit registry" (PluginContext.mcpToolRegistry: enumerate + invoke() every plugin's tools in-process) and an MCP server (registerMcpToolProvider → mcp__boss__*, attachable to Claude Code). We wrap these, not reinvent them.
  • One keystone unlocks four features. NodeType (enum) → NodeSpec (registry entry). After it, tool-nodes, browser-tool-nodes, and agent-nodes are all "register a spec at runtime."
  • A "lanager" = an agent-driven workflow = GraphSnapshot v2 (nodes+edges + metadata) where agent-node config lives inside node.config; a lanager node = a nested sub-workflow run as an async job.
  • Browser is not a stateless tool. It becomes a separate stateful SessionRegistry subsystem; tools thread a session_id. Statefulness is externalized so the tool interface stays clean.
Central decision Replace the NodeType enum with a runtime NodeSpec registry fed by a unified ToolSource layer. Everything else (tool-nodes, agent-nodes, MCP authoring, templates) is additive on top of that seam - but its config-schema shape must be proven by a spike before P0 freezes it.

01Goals & Non-goals

Goals

  • Every tool in the host mcpToolRegistry is usable as a workflow node (dynamic, RBAC-filtered).
  • Flow connects OUT to third-party MCP servers (stdio + HTTP/SSE); their tools also become nodes.
  • Flow registers a fixed set of MCP tools so an attached agent (Claude Code) can create/edit/run workflows, lanagers, and prompts.
  • A node can BE an agent ("lanager node"); a lanager node can nest a sub-workflow (subagent).
  • A prompt registry + builder UI: compose base + rules + glossary + goals + tool-allowlist; authorable by user or agent.
  • Lanager templates (JSON) import/export with a gallery; Flow orchestrates browser + other plugins' tools, not just RPA.
  • Existing 12-node flows keep loading and running unchanged (behavior-preserving migration).

Non-goals scope guard

  • Not hosting our own MCP server - terminal-tab owns the single boss server; two would collide.
  • Not building a generic host-level tool registry - the host already has one; we consume it.
  • Not a tool-per-artifact MCP surface - a small fixed generic tool set that takes names/ids as args (the provider is non-reactive).
  • Not a full visual prompt-graph / multi-agent-swarm UI (reviving deleted #93 literally) - single agent nodes + nesting only.
  • Not replacing the DAG executor - it stays; we make it kind-agnostic and add an async job wrapper.
  • Not a stable-node-id expression engine rewrite now - keep title-based {{ }} refs; enforce unique titles on generated graphs (deferred, see D3).

02Architecture

  • NodeRegistry (new) - runtime map kind-id → NodeSpec{ports, configFields, runMode, usesSession, executor}. Replaces the NodeType enum + four when blocks. Palette + dispatch read from it.
  • ToolSource (new) - stateless list()/invoke(name, argsJson). Impls: BossRegistryToolSource (wraps mcpToolRegistry), ExternalMcpToolSource (new MCP client), FlowBrowserToolSource (thin façade over the stateful SessionRegistry, threads session_id).
  • SessionRegistry (new) - owns long-lived browser sessions (session_id → BrowserIntegration + per-session mutex). A RunContext redesign: N sessions instead of one fenced session.
  • FlowController (new, headless) - authors/patches GraphSnapshot JSON at the storage layer (graph:<tabId>); runs graphs via the UI-free FlowExecutor; exposes an async run-job model (runId + poll).
  • FlowMcpToolProvider (new) - a fixed generic tool set (flow_*, lanager_*, prompt_*) registered into the host's boss MCP server via registerMcpToolProvider.
  • AgentRuntime (new) - provider-agnostic Kotlin tool-loop (port of RISA's runner); agent-node executor; tool-allowlist drawn from ToolSource; subagent = nested lanager async job.
  • PromptRegistry (new) - composable prompts persisted via pluginStorageFactory; builder UI; prompt-authoring MCP tools.
  • FlowExecutor (exists, unchanged core) - parallel topological DAG, coroutine-per-node. Stays kind-agnostic; only its session handling moves to SessionRegistry.
  • Host (exists) - mcpToolRegistry, registerMcpToolProvider, McpServerController.attach("CLAUDE_CODE"), BrowserService, secretDataProvider, pluginStorageFactory. terminal-tab hosts the boss server.

03Data flow

  • Authoring is storage-seated: flow_add_node patches the GraphSnapshot JSON at graph:<tabId> - no open tab required. A live tab, if any, re-reads storage on the Main thread.
  • Running is async: flow_run returns a runId immediately (the registry invoke is fenced at 60s; a browser DAG can exceed that). The agent polls flow_status/flow_result.
  • Tools resolve through ToolSource: a tool-node executor calls invoke(name, argsJson); isError is thrown as ExecError to feed the DAG's exception-based failure model.

04Data model & contracts

  • GraphSnapshot v2 - adds schemaVersion: Int (gate old builds) + metadata: FlowMeta?{name, version, description, inputs}. nodes/edges/nextId unchanged. No sidecar agents map - agent config lives in node.config (F6).
  • NodeModel.type: NodeType → String kind-id. Legacy enum names ("HTTP") map 1:1 to registry ids; new ids namespaced tool:boss:<name>, tool:ext:<server>/<name>, agent, lanager, browser:<action>.
  • NodeSpec (runtime, not serialized) - {id, label, inputs, outputs, configFields, runMode, usesSession, executor}. Built-ins registered at startup; tool/agent specs registered dynamically.
  • ConfigField extended - add FieldType.JSON (raw editor) + NUMBER; nested/array tool inputs stored as a JSON blob in config and marshalled to argsJson (F3).
  • Tool-node config caches toolRef + a schemaSnapshot at author time, so a saved flow renders/validates even when the tool is absent at load (F4).
  • Prompt - {id, name, base, rules[], glossary[], goals[], toolAllowlist: ToolRef[], version}, persisted at prompt:<id> + prompts:index.
  • New storage keys - prompt:*, template:*, mcpservers:config (external servers; secrets held separately in secretDataProvider), settings. Existing: graph:<tabId>, runstate:<tabId>.

07Blind spots red-team

Found by an independent agent told to break this plan. Structural flaws and things the plan does not see.

Structural flaws - folded into the plan above (F1-F6)
F1 · 60s invoke timeout kills synchronous flow_run
A browser DAG (per-node waits up to 15-20s) can exceed the registry's 60s fence. Fix applied: async job model - flow_run returns runId, agent polls flow_status/flow_result. The tool contract is async from P2's first line.
F2 / F12 · stateless ToolSource.invoke doesn't fit stateful browser sessions
A browser action needs a session that outlives a single call and that an external MCP caller (no RunContext) can reach. Fix applied: browser statefulness externalized into a new SessionRegistry (N sessions, per-session mutex) - a real RunContext redesign (P3), not a wrapper. ToolSource stays stateless by threading session_id.
F3 · flat ConfigField + scalar args can't hold nested JSON-Schema
FieldType is TEXT/TEXTAREA/SELECT/BOOL; ConfigReader reads top-level scalars only. Many tool schemas have nested objects/arrays. Fix applied: extend the config model (JSON/NUMBER) + a JSON fallback, and prove the mapping in P-spike before P0 freezes NodeSpec.
F4 · tool-nodes reference tools that may be absent at load
tools is an async StateFlow; the owning plugin may be unloaded. A saved flow would have no schema and hit ExecError("not runnable"). Fix applied: cache toolRef+schemaSnapshot in config; "tool unavailable" is a first-class node state.
F5 · headless façade must be storage-seated, not component-reaching
FlowGraphState is a private, UI-thread Compose field of a live tab; authoring may happen with no tab open, and off-thread structural edits race the compositor. Fix applied: FlowController patches GraphSnapshot JSON in storage (the existing openImportedInNewTab path) and runs the UI-free executor.
F6 · agent config in a sidecar map fights every per-node path
PlanNode carries only config; removeNode/import/export/inspector all key off node.config. A separate agents map orphans on delete and needs threading through the executor. Fix applied: agent config lives inside node.config.
Remaining watch-items (mitigated, not eliminated)
F7 · non-reactive provider vs a growing tool set
McpToolProvider.tools() is queried once; the bridge dedups first-wins and silently skips name collisions. Mitigation: a fixed generic tool set; all Flow tools flow_-prefixed to dodge the 15 reserved names + cross-plugin collisions.
F9 · external MCP process lifecycle on a packaged app
macOS GUI apps don't inherit shell PATH → npx/uvx stdio servers fail; plus zombie subprocesses + secret egress. Mitigation: P7 is last, flagged, resolves binaries via a login shell, reaps on dispose().
F11 · title→id {{ }} migration rewrites substrings inside config
Refs are resolved by title inside arbitrary strings; switching to ids is a content migration, not a rename (and SET already passes emptyMap() for node outputs). Mitigation: defer D3 - keep title refs, enforce unique titles on generated graphs.
